# 講師ガイド

## 1. 研修のねらい

この研修は、Rの操作研修ではなく、教育課題をデータで検討し、授業改善と学生支援へつなげるFDです。
コードが実行できることより、次を重視してください。

- 学生の性格や能力へ原因を固定しない
- ログで観測できる範囲を明示する
- 授業設計と学生の経験を分析へ戻す
- 支援を非懲罰的かつ選択可能にする
- 予測性能と教育効果を区別する

## 2. 想定参加者

- 大学教員
- FD・教育支援担当者
- インストラクショナルデザイナー
- IR・ラーニングアナリティクス担当者
- 学生相談・学修支援担当者

1グループ3〜5人、全体12〜30人程度を想定しています。個人受講も可能です。

## 3. 事前準備

### 講師

1. 教材とRスクリプトを通して実行する
2. CSVの文字コードと相対パスを確認する
3. 参加者のR経験を確認する
4. 実在データを使わないことを説明する
5. 組織の教育データ方針、相談窓口、倫理審査手続を確認する

### 参加者

- RとRStudio等の実行環境
- `tidyverse`、`lubridate`、`broom`、`yardstick`
- 教材一式のダウンロード
- 自分の授業で改善したい教育課題を一つ考える

研修前に[R実行環境の構築](07-r-environment-setup.md)を案内し、
`R/03-check-environment.R`の完了画面を確認してください。
R環境の設定時間は3時間に含めません。初学者には完成済みスクリプトを配布してください。

## 4. 初級編の進行

| 時間 | 内容 | 講師の役割 |
|---:|---|---|
| 0–15分 | 導入ケース | 原因を学生へ固定する発言を問いへ戻す |
| 15–35分 | 教育課題の中立的記述 | 観測事実と評価語を分ける |
| 35–60分 | 授業設計対応表 | 必須・任意、評価対象を確認する |
| 60–90分 | データ品質とR読込 | コード操作を支援し、意味の確認を優先する |
| 90–100分 | 休憩 |  |
| 100–130分 | 週次可視化 | 中央値だけで結論を出させない |
| 130–150分 | 反例 | 低活動・高得点等を議論する |
| 150–170分 | 授業改善案 | 学生への説明と副作用も書かせる |
| 170–180分 | 共有・まとめ | 次に確認する情報を言語化する |

### 初級編で使う問い返し

- それはログに記録された事実ですか、解釈ですか。
- 同じログになる別の理由はありますか。
- この活動は授業で必須でしたか。
- 学生本人へ何を確認しますか。
- 教材や締切を変える余地はありますか。
- この結論を学生へ説明できますか。

## 5. 中級編の進行

| 時間 | 内容 | 講師の役割 |
|---:|---|---|
| 0–20分 | 支援ケース | 「予測」より先に支援目的を確認する |
| 20–45分 | 構成概念マップ | 指標と概念の間へ反例を入れる |
| 45–65分 | 予測時点・漏洩 | 運用時点で利用可能かを問う |
| 65–100分 | 基礎モデル | 係数を原因と解釈させない |
| 100–110分 | 休憩 |  |
| 110–135分 | 支援容量と閾値 | 全員支援との組合せを検討する |
| 135–155分 | 公平性と支援到達 | モデル以外の運用差を見る |
| 155–170分 | 介入評価 | 送信、到達、実施、成果を分ける |
| 170–180分 | 学生説明・まとめ | 訂正、拒否、選択の経路を確認する |

### 中級編で使う問い返し

- 何を改善するための予測ですか。
- 支援対象にならなかった学生には何を提供しますか。
- その特徴量は判定時点で存在しましたか。
- 誤警告と見逃しの影響は同じですか。
- 支援は学生へ実際に届きましたか。
- 学生は分析の理由を知り、訂正できますか。

## 6. 修士発展編の進行

心理・教育系の修士1年では、R操作の習熟より、理論、測定、研究デザイン、教育的介入の接続を評価します。
初級・中級を修了した後の3時間として実施します。

| 時間 | 内容 | 講師の役割 |
|---:|---|---|
| 0–25分 | 研究質問の六つの型 | 予測・説明・因果・評価を区別する |
| 25–60分 | 構成概念妥当性 | 理論からログ指標までの飛躍を見つける |
| 60–85分 | エビデンス台帳 | 不一致を欠陥ではなく検討対象にする |
| 85–95分 | 休憩 |  |
| 95–125分 | 介入ロジックモデル | 警告から教育成果までを分解する |
| 125–155分 | 評価デザイン | 主張に必要な比較と仮定を確認する |
| 155–170分 | 倫理・データ管理 | 分析後ではなく計画時に組み込む |
| 170–180分 | ピアレビュー | 最も重要な飛躍と修正案を共有する |

### 心理・教育系で使う問い返し

- その構成概念をどの理論に基づいて定義しましたか。
- ログへ現れない同じ心理過程はありますか。
- 異なる心理過程が同じログになる可能性はありますか。
- 自己報告とログが一致しない場合、何を学べますか。
- その研究デザインは、関連と因果のどちらを支持しますか。
- 教育成果の前に、どの近位要因が変わる想定ですか。
- 効果がなかった場合、理論、実装、到達のどこを確認しますか。

### 情報系授業での90分圧縮版

情報系では、初級・中級のR操作やモデル作成を別授業で扱う前提とし、教育的妥当性の検討へ集中します。

| 時間 | 内容 | 成果物 |
|---:|---|---|
| 0–15分 | 予測・説明・因果・介入評価の区別 | 主張の書き換え |
| 15–35分 | 構成概念とログ指標 | 妥当性メモ |
| 35–55分 | ロジックモデル | 支援到達までの図 |
| 55–75分 | 評価・公平性・副作用 | 評価指標表 |
| 75–90分 | ピアレビュー | モデルカードへの教育的追記 |

情報系では「モデルの精度が上がった後に何を確認すべきか」を中心に問い、アルゴリズムの説明は圧縮します。

## 7. グループ討議の運営

各グループで役割を分けると、分析担当者だけの視点に偏りにくくなります。

- 教員役：授業目的と実行可能な変更を考える
- 学生役：通知の受け止めと選択可能性を考える
- 支援者役：連絡後の相談とリソースを考える
- データ担当役：観測範囲、欠測、誤差を確認する
- 倫理担当役：不利益、公平性、透明性を確認する

途中で役割を交代してください。

## 8. 評価方法

テスト得点より、成果物をルーブリックで評価します。

| 観点 | 3：十分 | 2：部分的 | 1：要改善 |
|---|---|---|---|
| 教育課題 | 中立的で変更可能な要因を含む | 課題はあるが原因を先取り | 学生属性へ固定 |
| データ解釈 | 事実・説明・代替説明を区別 | 一部を区別 | 指標を直接的な学習とみなす |
| 補完情報 | 成果・学生の声・授業設計を統合 | 一種類を追加 | ログのみ |
| 教育的対応 | 全員支援と追加支援を設計 | 対象者への対応のみ | 警告のみ |
| 学生主体性 | 説明、選択、訂正を含む | 一部を含む | 自動決定 |
| 評価 | 運用・成果・公平性・副作用を含む | 成果のみ | モデル精度のみ |

修士発展編では、[修士発展課題と評価ルーブリック](09-masters-assignment.md)を使います。

## 9. センシティブな議論への対応

参加者が実在学生の事例を話す場合は、氏名、学籍番号、具体的な診断名、少人数属性を共有しないようにします。
相談・障害・経済状況等は、予測精度を上げるために安易に特徴量へ加えません。

次の発言が出た場合は、教育上の問いへ戻します。

- 「この学生はやる気がない」
- 「クリックが少ないので学んでいない」
- 「モデルが高リスクと言っているので連絡する」
- 「精度が高いので公平である」
